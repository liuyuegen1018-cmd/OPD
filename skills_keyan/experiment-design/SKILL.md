## 工作流程

### Step 1：明确实验目标

**从理论推论提取实验目标**

```markdown
## 实验目标

### 主目标
验证核心理论推论：
{main_objective}

### 子目标
1. 验证推论 1：{sub_objective_1}
2. 验证推论 2：{sub_objective_2}
3. 验证推论 3：{sub_objective_3}
```

---

### Step 2：数据集选择

**数据集评估维度**：

| 维度 | 问题 |
|------|------|
| **相关性** | 是否匹配研究问题？ |
| **规模** | 是否足够大以得到统计显著结果？ |
| **公开性** | 是否公开可获取？ |
| **社区认可** | 是否为领域标准 benchmark？ |
| **多样性** | 是否覆盖多种场景？ |

**数据集选择模板**：

```markdown
## 数据集

### 主数据集

| 数据集 | 规模 | 任务类型 | 选择理由 |
|--------|------|----------|----------|
| {dataset_1} | {size} | {task} | {reason} |
| {dataset_2} | ... | ... | ... |

### 辅助数据集

| 数据集 | 用途 |
|--------|------|
| {dataset_3} | 泛化性验证 |
| {dataset_4} | 特定场景测试 |

### 数据预处理

- **划分**：训练/验证/测试 = {ratio}
- **预处理步骤**：
  1. {step_1}
  2. {step_2}
```

---

### Step 3：基线方法选择

**基线类型**：

| 类型 | 说明 | 数量 |
|------|------|------|
| **经典方法** | 领域开创性工作 | 1-2 个 |
| **SOTA 方法** | 当前最佳方法 | 2-3 个 |
| **消融基线** | 本方法的简化版本 | 2-3 个 |
| **启发式方法** | 简单规则/基线 | 1 个 |

**基线选择模板**：

```markdown
## 基线方法

### 主要基线

| 方法 | 年份 | 会议 | 核心思想 | 为何选择 |
|------|------|------|----------|----------|
| {baseline_1} | 2024 | NeurIPS | {idea} | SOTA |
| {baseline_2} | 2024 | ICLR | {idea} | 理论相关 |
| {baseline_3} | 2023 | ICML | {idea} | 经典方法 |

### 消融基线

| 变体 | 修改内容 | 验证目的 |
|------|----------|----------|
| Ours w/o component A | 移除组件 A | 验证 A 的必要性 |
| Ours w/o component B | 移除组件 B | 验证 B 的必要性 |
| Ours (简化版) | 仅保留核心 | 验证复杂度的必要性 |

### 公平性保障

- 相同数据集划分
- 相同评估指标
- 相同计算资源（如 GPU hours）
- 超参数调优预算相同
```

---

### Step 4：评估指标定义

**指标选择原则**：
- 与研究目标对齐
- 领域标准指标
- 多维度评估

**指标定义模板**：

```markdown
## 评估指标

### 主要指标

| 指标 | 公式 | 含义 | 方向 |
|------|------|------|------|
| Accuracy | $\frac{TP+TN}{N}$ | 准确率 | ↑ |
| F1 Score | $2 \cdot \frac{P \cdot R}{P+R}$ | F1 值 | ↑ |
| AUC | - | ROC 曲线下面积 | ↑ |

### 辅助指标

| 指标 | 用途 |
|------|------|
| Latency | 推理速度 |
| Memory | 内存占用 |
| #Params | 参数量 |

### 统计显著性

- 显著性检验：t-test / Wilcoxon
- 显著性水平：p < 0.05
- 重复次数：n = {n_runs} 次随机种子

### 效果量计算

$$
\text{Improvement} = \frac{\text{Ours} - \text{Baseline}}{\text{Baseline}} \times 100\%
$$
```

### Step 5：实验设计

| 方法 | Dataset 1 | Dataset 2 | Dataset 3 | Avg |
|------|-----------|-----------|-----------|-----|
| Baseline 1 | - | - | - | - |
| Baseline 2 | - | - | - | - |
| Baseline 3 | - | - | - | - |
| **Ours** | **-** | **-** | **-** | **-** |

### 分析维度
1. 整体性能对比
2. 不同任务类型的表现
3. 与 SOTA 的差距分析
```

|--------|----------|----------|

| w/o Component B | {what} | 性能下降 Y% |
| w/o Component C | {what} | 性能下降 Z% |

### 结果表格

| 变体 | Dataset 1 | Dataset 2 | Δ |
|------|-----------|-----------|---|
| Full Model | - | - | - |
| w/o A | - | - | ↓ X% |
| w/o B | - | - | ↓ Y% |
| w/o C | - | - | ↓ Z% |
```

## 设计原则

### 公平性原则

1. **相同数据**：所有方法使用相同数据划分
2. **相同指标**：统一评估标准
3. **相同资源**：公平分配计算预算
4. **透明报告**：公开所有超参数和配置

### 可复现原则

1. **固定随机种子**
2. **记录环境依赖**
3. **版本控制代码**
4. **保存原始日志**

### 全面性原则

1. **多数据集**：不局限于单一 benchmark
2. **多指标**：不只看单一指标
3. **消融验证**：分析各组件贡献
4. **边界分析**：探索方法局限
