# 一人科研部门前端页面设计说明

## 设计定位

该前端原型面向”一人科研部门”产品概念：用户不是直接面对复杂的自动科研 pipeline，而是管理一个由多个数字员工组成的科研部门。每个数字员工承担固定阶段职责，用户通过部门、项目、产出、看板四个视角了解科研工作如何推进。

页面不做营销展示，首屏即进入工作台。整体风格以科研管理工具为主，强调清晰、可扫描、低干扰和便于长期使用。

## 页面结构

工作台包含四个子页面：

1. 部门概况
2. 项目进展
3. 员工管理
4. 物料管理
5. 数字看板

左侧为固定导航栏，展示产品名称和五个页面入口。右侧为主工作区，不同页面切换时保留相同的整体视觉结构，但展示的信息重点不同。

顶部操作按钮随页面语境变化：

- 部门概况：`新建研究任务`
- 项目进展：`暂停当前项目`、`重新运行阶段`
- 员工管理：`新增员工`
- 物料管理：`提交指导`、`要求重新生成`
- 数字看板：`刷新`、时间范围筛选

### 顶部指标区

部门概况顶部展示五个部门级指标：

- 运行中任务
- 数字员工
- 已生成产出
- 等待审批
- 剩余阶段点数

这些指标只在部门概况页面出现。项目进展和部门产出页面不再重复展示，避免每个页面顶部信息过重。

### 任务池概览

部门概况中的项目模块定位为“任务池概览”，用于快速判断部门当前有哪些任务在跑，而不是展开项目排期。每张项目卡片包含：

- 项目名称
- 当前状态
- 当前负责人
- 是否阻塞
- 最近产出

用户点击项目卡片后，当前页面中的流程状态、员工状态会围绕所选项目更新。更细的 stage、排期和风险处理入口放在项目进展页面。

### 部门运行流程

部门概况中增加“部门运行流程”模块，用横向流程卡片表达自动科研的基本运行方式和当前状态。

流程按数字员工职责分为八段：

- 研究定义：研究策略师
- 文献发现：文献分析师
- 知识综合：假设设计师
- 实验构建：实验工程师
- 结果分析：数据分析师
- 论文生成：论文写作者
- 质量审查：同行评审员
- 归档发布：引用审计员

每个流程节点展示：

- 流程段名称
- 负责数字员工
- 当前状态：完成、运行中、等待、阻塞

该模块只需要让用户理解“谁负责哪一段、现在跑到哪里”，不展开复杂的底层 stage 细节。

### 数字员工整体状况

数字员工以紧凑卡片展示，支持两到三列排布。每张员工卡片展示：

- 员工中文名和英文角色名
- 当前正在做什么
- 当前绑定项目
- 负责阶段
- 已产出数量
- 状态标签

点击员工卡片后，下方展示该员工的详细信息。

### 员工详情

员工详情包含三类信息：

- 当前工作：当前任务、负责阶段、当前项目
- 工作记录：近 30 周活跃度热力图
- 人事信息：入职天数、员工类型、累计完成项目、当前负载、触发器响应
- 核心技能：该数字员工擅长的能力标签和适用阶段

这样设计的目的是强化“数字员工”作为部门成员的产品心智，而不是仅仅把它们看作 pipeline 阶段标签。

### 员工技能说明

员工详情中增加“核心技能”模块，用于解释该数字员工适合处理什么问题。技能模块不做复杂能力评估，只展示用户决策需要的信息。

技能模块包含：

- 技能标签：3-5 个短标签
- 能力说明：一句话说明该员工擅长什么
- 适用阶段：对应的 pipeline stage 范围

示例：

```text
┌──────────────────────────────┐
│ 核心技能                      │
│ [实验设计] [代码生成]          │
│ [baseline] [metrics contract] │
│                              │
│ 能力说明：擅长把研究假设转成   │
│ 可运行实验，并修复运行错误。   │
│                              │
│ 适用阶段：Stage 9-13          │
└──────────────────────────────┘
```

各数字员工技能示例：

- 研究策略师：选题拆解、研究问题定义、任务边界设定、评价指标选择
- 文献分析师：文献检索、相关性筛选、知识卡片抽取、引用初筛
- 假设设计师：研究空白识别、假设生成、可验证性评估、创新性判断
- 实验工程师：实验设计、代码生成、baseline 设计、metrics contract、错误修复
- 数据分析师：统计分析、结果表格、显著性检验、失败归因
- 论文写作者：论文大纲、方法描述、结果叙述、修改整合
- 同行评审员：逻辑审查、质量门控、反驳式评审、风险指出
- 引用审计员：引用校验、归档、导出、最终一致性检查

### 数字员工项目排班

数字员工项目排班放在项目进展页顶部，因为它不是某一个项目内部的详情，而是整个一人科研部门的资源占用视图。

该模块用于回答：

- 每个数字员工未来几天在做哪个项目
- 当前项目会占用哪些员工
- 哪些员工已经被其他项目占用
- 哪些交接点可能发生排期冲突

排班表是部门级视图。横轴是日期，纵轴是数字员工。每个排班色块都以“项目名 + 阶段任务”的方式展示，表达某个员工在某段时间被哪个项目占用。

当用户点击下方项目卡片后，排班表中属于当前项目的任务色块高亮，其他项目任务保持弱化显示。这样既能看到当前项目的资源安排，也能看到它和其他项目之间的排期冲突。

排班色块内容规则：

- 主文本：项目简称，例如 `GNN项目`、`多模态`、`代码评审`
- 副文本：阶段任务，例如 `实验构建`、`文献筛选`、`结果分析`
- 空白日期：表示该员工未被项目占用或等待交接

示例：

```text
GNN项目 · 实验构建
多模态 · 文献筛选
代码评审 · 结果分析
RL项目 · 研究定义
```

视觉规则：

- 当前项目任务：高饱和色块
- 其他项目任务：浅色或灰色
- 阻塞任务：红色或橙色边框
- 等待任务：虚线边框

### 项目进展卡片

数字员工项目排班下方展示项目卡片列表。项目卡片承担“选择当前项目”的作用，而不是承担完整项目详情展示。

每张卡片包含：

- 项目名称
- 项目主题
- 当前状态
- 当前 stage
- 当前负责人
- 项目进度

用户点击项目卡片后，下方当前项目阶段计划切换为该项目的推进视图。

### 当前项目概览条

项目进展卡片下方增加当前项目概览条，避免用户在部门级排班和当前项目阶段计划之间迷失。

当前项目概览条展示：

- 当前项目名称
- 当前阶段
- 当前负责人
- 项目状态
- 下一交接员工
- 最近产出

该模块是项目进展页的上下文锚点。用户切换项目后，概览条、排班高亮、当前项目阶段计划和风险摘要同步变化。

### 当前项目阶段计划

当前项目阶段计划展示从研究定义到归档发布的完整项目推进路径。它只展示当前选中项目，不展示其他项目。

横轴是阶段序列，纵轴是科研流程段。每一行代表一个阶段组，例如：

- 研究定义
- 文献发现
- 知识综合
- 实验构建
- 结果分析
- 论文生成
- 质量审查
- 归档发布

每个阶段组用横向色块表示持续区间，色块内显示阶段名称，左侧显示负责人。

该模块用于回答：

- 当前项目走到了哪个阶段
- 当前阶段由哪个数字员工负责
- 哪些阶段已经完成、运行中、等待或阻塞
- 后续阶段是否受当前阻塞影响
- 项目预计什么时候进入论文写作、质量审查和归档发布

### 风险摘要

项目进展页右侧保留风险摘要，用于提示排期和推进风险。例如：

- 某个员工重试次数较多
- 某个阶段燃尽变慢
- 后续员工等待上游产出

风险摘要需要比普通提示更具体。每条风险至少展示：

- 风险类型：阻塞、延迟、重试、等待、资源冲突
- 影响对象：项目、阶段、数字员工
- 当前状态：是否已经阻塞
- 影响程度：低、中、高
- 最近发生时间
- 简短原因

风险卡片可以点击。点击后在右侧或下方展开风险详情，展示：

- 详细原因
- 涉及阶段
- 涉及员工
- 阻塞来源
- 已尝试的自动修复动作

### 页面分区说明

数字看板分为四个主要区域（按优先级排列）：

1. **论文列表区**：论文卡片展示，放在最上面作为核心内容
2. **核心指标区**：5个KPI卡片，展示科研产出概览
3. **数据图表区**：产出趋势图 + 研究主题分布图
4. **流程效能区**：6个阶段的耗时分析 + 瓶颈识别

### 核心指标卡片

顶部展示五个核心指标：

| 指标 | 含义 | 计算方式 | 趋势展示 |
|------|------|----------|----------|
| 总产出 | 论文总数 | `status=done` 的项目数 | 本周新增数 |
| 完成率 | 项目成功走到终点的比例 | `完成数 / 总启动数` | 环比变化 |
| 平均周期 | 从启动到归档的平均天数 | `avg(completed_at - created_at)` | 环比变化 |
| 活跃项目 | 正在运行的项目数 | `status=running` | - |
| 阻塞率 | 当前被阻塞的项目占比 | `blocked / total` | 环比变化 |

每个指标卡片包含：
- 图标 + 指标名称
- 主数值
- 趋势副标签（环比变化或本周新增）
